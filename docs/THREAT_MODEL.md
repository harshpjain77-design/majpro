# docs/THREAT_MODEL.md — Threat Model and Trust Boundaries

## 1. System Overview & Trust Boundaries
The AI Cyber Defense Platform operates across distinct trust zones:
- **Zone 0: Monitored Log Sources (Untrusted Input)**:
  - Security logs generated by remote or local machines.
  - *Threat*: Attackers control usernames, URLs, command-line arguments, user agents, or SSH client banners, allowing log injection, terminal escape sequence injection, or prompt injection intended to fool downstream LLM analyzers.
- **Zone 1: Collector Boundary**:
  - Python collectors running locally on monitored endpoints (Kali Linux, Windows Server).
  - *Threat*: Privilege escalation, denial of service via high-volume log flooding, local file tampering.
- **Zone 2: Transport & Central Ingestion Boundary**:
  - Network link transmitting logs to FastAPI ingestion endpoint.
  - *Threat*: Man-in-the-middle eavesdropping, unauthorized log injection, replay attacks, resource exhaustion.
- **Zone 3: Central Processing, Storage & AI Engine**:
  - Core database, detection correlation, LLM investigation assistant, automated response engine.
  - *Threat*: SQL/NoSQL injection, prompt injection leading to unauthorized automated response execution, denial of service.

---

## 2. Threat Analysis (STRIDE)

| Threat Category | Potential Attack Vector | Platform Mitigation |
|:---|:---|:---|
| **Spoofing** | Rogue agent submitting fabricated authentication logs to frame legitimate users or mask attacks. | Agent authentication via pre-shared API keys / TLS client certificates; source host validation. |
| **Tampering** | Modifying checkpoint files to replay logs or skip suspicious entries. | Checkpoints stored in protected user directories with file permission restrictions; checksumming. |
| **Repudiation** | An attacker claims log entries were forged or altered in transit. | Immutable raw event preservation (`raw_event`), content hashing (`event_id` fingerprint), structured audit logging. |
| **Information Disclosure** | Leakage of sensitive credentials or password hashes contained inadvertently in raw logs. | Data scrubbing/masking filters before storage; role-based access control; no secrets in git. |
| **Denial of Service** | Log bomb / flood aimed at exhausting collector CPU, memory, or ingestion storage. | Stream processing, batch chunking, rate limiting on ingestion API, payload size caps. |
| **Elevation of Privilege** | LLM prompt injection manipulating automated response engine to isolate legitimate critical servers. | LLM is advisory only; zero direct command execution by LLM; human-in-the-loop approval gating; strict allowlist of response actions. |

---

## 3. Defensive Engineering Principles
- **No Direct Shell Execution**: Never pass raw event data directly to shell commands (`subprocess.run(shell=True)` is forbidden).
- **Type Safety and Input Validation**: Strict Pydantic models validate all incoming data before it touches storage or detection engines.
- **Fail-Safe Response Engine**: The automated response engine defaults to dry-run mode, requires explicit analyst sign-off for disruptive actions, and maintains reversible rollback operations.
